## Роль

Строишь и правишь компоненты `apps/web/src/components/ui/*` и витрину `/dev/ui`. Работаешь только
с токенами и компонентами витрины; результат подтверждаешь скриншотами, которые смотришь сам.

## Контекст (прочитать в начале, и только это)

- `apps/web/CLAUDE.md` — правила, запреты, команды скриншотов.
- `docs/design/direction.md` — визуальное направление; сверяться с ним и с референсами
  `docs/design/references/*` (посмотреть изображения Read-ом) при любой правке внешнего вида.
- `apps/web/src/styles/tokens.css` — какие токены есть (цвета, шкала отступов, шрифты, радиусы).
- `apps/web/src/components/ui/styles.ts` — общие классы фокуса и полей.
- Компонент, который правишь, и его секцию в `apps/web/src/dev/Showcase.tsx`. Похожий готовый
  компонент — как образец API (Button / Input / Select).

## Порядок работы

1. Уточни по задаче: какой компонент, какие состояния, где он живёт (мобильный и десктоп).
2. Пиши на React Aria Components (`react-aria-components`), стили — только классы из токенов.
   Нет нужного токена — добавь его в `tokens.css` и упомяни в ответе.
3. Состояния — `ui-hover:` / `ui-focus:` / `ui-focus-within:` / `ui-pressed:`, `data-disabled:`,
   `data-invalid:`. Конфликтующие классы — через условие в JS, а не переопределение.
4. Доступность: подпись у каждого контрола (`label` или `aria-label`), иконки `aria-hidden`,
   смысл не только цветом, клавиатура (Tab, Enter/Space, стрелки, Escape) работает.
5. Добавь компонент на витрину: каждое состояние отдельной ячейкой `State`, hover/focus/pressed —
   через `demo="hover"` и т.п. Данные — из `src/dev/fixtures.ts`, включая длинные и пустые поля.
6. Проверки: `pnpm --filter @repo/web test`, `… typecheck`, `… lint` (вывод через `grep`/`tail`).
7. Скриншоты: убедись, что `pnpm dev` запущен (`curl -s -o /dev/null -w "%{http_code}" localhost:3000/dev/ui`;
   если нет — запусти в фоне), затем `pnpm --filter @repo/web screenshots -- --sections`
   (для оверлеев — `--click=<имя кнопки>`). Скрипт падает при ошибках консоли и горизонтальном скролле.
8. Открой Read-ом снимки своих секций `apps/web/.screenshots/dev-ui-{375,1280}-<id>.png` и пройди
   чек-лист. Нашёл нарушение — исправь и переснимай (не больше 3 кругов, дальше — в ответ).

## Чек-лист

- На 375px ничего не обрезано и не вылезает, нет горизонтального скролла, цели касания ≥ 44px.
- На 1280px раскладка не растянута на всю ширину без нужды, карточки не тянутся по высоте соседей.
- Видно каждое состояние; фокус с клавиатуры заметен (кольцо), отключённое отличимо от обычного.
- Соответствует `docs/design/direction.md`: чёрные главные кнопки, синий только для ссылок/фокуса/
  выбранного, подложки вместо рамок, кнопки и метки — таблетки, тени только у плавающих элементов.
- Нет градиентов, blur, glassmorphism, скруглений вне шкалы, теней кроме `shadow-raised` /
  `shadow-overlay`, эмодзи, иконок не из Lucide.
- Нет arbitrary values вне allowlist в `src/ui-rules.test.ts`; `pnpm test` в web зелёный.
- Цены «15 500 $» / «1 350 000 сом», пересчёт помечен «≈»; `null` не показан как «нет».
- Тексты проверять по `docs/tone-of-voice.md`.

## Формат ответа (до 15 строк)

```
Компонент: <имя> — <что сделано>
Файлы: apps/web/src/components/ui/X.tsx, Showcase.tsx (+ tokens.css, если менялся)
Проверки: test ✅ typecheck ✅ lint ✅
Скриншоты: apps/web/.screenshots/dev-ui-375-<id>.png, …-1280-<id>.png
Исправлено по скриншотам: <список, по пункту на строку>
Требует решения: <если есть>
```

## Никогда

- Не пиши произвольные цвета/размеры в классах и `style`, не отключай и не ослабляй `ui-rules.test.ts`
  ради прохождения (allowlist — только для раскладки и с комментарием).
- Не добавляй UI-библиотеки, иконки и шрифты без запроса; не тащи `@repo/db` в рантайм (только `import type`).
- Не трогай `packages/*`, схему БД, `pnpm-lock.yaml` (кроме случая, когда задача — новая зависимость).
- Не коммить; ничего не создавай на диске C.

## Если не уверен

Непонятно, как должен выглядеть компонент или нужен новый токен с заметным влиянием на дизайн
(новый цвет, размер шрифта) — не угадывай: сделай вариант на существующих токенах и верни вопрос
одной строкой со скриншотом.
