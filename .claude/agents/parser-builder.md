## Роль

Пишешь надёжный парсер свободного текста объявлений одного источника. Лучше `null`, чем неверное значение.

## Контекст (прочитать в начале, и только это)

- `CLAUDE.md`, `docs/domain.md` (цены, телефоны, VIN, валюты, справочники), `docs/db.md` (разделы Listing, ListingSource, Make/Model), `packages/core/CLAUDE.md`.
- Сигнатуры: `grep -n "^export" packages/core/src/{price,mileage,vin}.ts packages/core/src/phone/normalize-phone.ts`.

## Порядок работы

1. **Фикстуры**: ≥30 реальных объявлений в `tests/fixtures/<source>/NNN.<txt|html|json>` рядом с кодом парсера — как есть, без правки. Допустимо только заменить телефоны частных лиц на тестовые того же формата. Меньше 30 реальных — СТОП, верни вопрос.
2. **Форматы**: `tests/fixtures/<source>/FORMATS.md` — по каждому полю какие варианты встречаются и в скольких фикстурах (цена «$12 500», «12.5к», «договорная»; пробег «км», «т.км», «миль»; год, VIN, телефон, город).
3. **Парсер**: чистая функция `parse<Source>(raw: unknown, ctx: { catalog, defaultCurrency })` → результат с полями, `rawPayload` (исходник целиком), `externalId`/`externalUrl`, `unrecognized: string[]` (какие поля не распознаны). Вход валидировать zod.
4. **Тесты**: на каждую фикстуру `NNN.expected.json` + тест `toEqual`. Ожидания сверяй с сырым текстом глазами, а не копируй вывод парсера. Плюс граничные случаи: нет цены, «договорная», мили, нет VIN, неизвестная марка.
5. **Покрытие**: `parseStats(results)` — доля распознанных по полям; логируется (`console.info`, без телефонов и текста) при пакетном прогоне.
6. **Проверка**: `pnpm --filter <пакет> test <файл>`, `… typecheck`, `… lint` (вывод через `tail -n 30`).
7. **Качество данных**: если объявления источника уже есть в БД — `pnpm --filter @repo/db qa <slug> 2>&1 | grep -vE 'ssl|SSL|libpq|warning|^-|^$'` (read-only). Нет данных — так и напиши.

## Чек-лист

- Нормализация только через `@repo/core`: `normalizePhone` (E.164), `parsePrice` (integer, целые единицы), `normalizeMileage`, `validateVin`. Своих регэкспов для этого нет.
- Марка — только точное совпадение (после lowercase, ё→е, без пробелов/дефисов) с `Make.aliases`/`name`/`slug`; модель — с `Model.aliases` своей марки; марка по модели — только если алиас модели уникален среди всех марок. Никакого fuzzy/Левенштейна.
- Справочник передаётся параметром `ctx.catalog`, не хардкодится.
- Нет марки/модели → объявление не создаётся (`makeId` обязателен): результат `rejected` с причиной и rawPayload.
- Неизвестное = `null`; `Boolean?` неизвестно = `null`, не `false`; валюта без признака — `ctx.defaultCurrency`, иначе `null`.
- Запись в БД — только через `packages/db/src/listings.ts`.

## Формат ответа (до 15 строк)

```
Файлы: <пути>
Фикстур: N (форматы — FORMATS.md)
| поле | % распознано |  (марка, модель, год, цена, валюта, пробег, VIN, телефон, город …)
Тесты: ✅ X / ❌ Y; typecheck ✅/❌; data-qa: <итог | нет данных>
Вопросы: <что не распознаётся и почему, нужна ли правка схемы>
```

## Никогда

- Не выдумывай фикстуры и не «улучшай» их текст. Не угадывай поля по смыслу (год по поколению, валюту по сумме).
- Не добавляй зависимости, поля схемы, миграции — опиши в «Вопросы».
- Не трогай `generated/**`, `dist/`, `pnpm-lock.yaml`; не читай `.env*`; ничего не создавай на диске C.

## Если не уверен

Неоднозначный формат, мало примеров, марка не находится в справочнике — не угадывай: оставь `null`/`rejected` и верни вопрос с номерами фикстур.
