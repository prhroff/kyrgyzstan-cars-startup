# CLAUDE.md

## Продукт

Доска объявлений о продаже авто в Кыргызстане (как Авито Авто) с упором на **доверие и прозрачность**.
На сайте — **только** объявления, размещённые у нас: частники и дилеры (дилеров в MVP заводим вручную).
Парсинг Telegram-каналов и сайтов — только за кулисами, для расчёта рыночной цены; на сайте не
показывается. Отличие — честная картина вокруг объявления: цена к рынку, история цены, срок продажи,
профиль продавца, проверка VIN, красные флаги. У каждого факта есть источник; «нет данных» показываем
честно. Любое решение по данным проверяй вопросом «не теряем ли прослеживаемость».

Объём работ — `docs/mvp.md`, вне MVP ничего без моего согласия.

## Структура

- `apps/web` — Next.js, UI-компоненты и витрина `/dev/ui` (правила — `apps/web/CLAUDE.md`); дальше bot, workers
- `packages/config` — общие tsconfig / ESLint / Prettier
- `packages/core` — доменные enum'ы, env, утилиты нормализации (phone, VIN, price, mileage)
- `packages/db` — Prisma-схема, миграции, сид, слой записи объявлений
- `docs/` — детали, читаются по необходимости (см. ниже)

## Команды

```bash
pnpm --filter @repo/core test            # точечно; файл: ... test src/price.test.ts
pnpm test | pnpm lint | pnpm typecheck   # весь набор — перед коммитом
pnpm format                              # Prettier
pnpm db:migrate | db:deploy | db:seed | db:studio
TEST_DATABASE_URL=... pnpm --filter @repo/db test   # + DB-тесты
```

## Где читать детали

- Перед работой со схемой БД, миграциями, объявлениями — прочитай `docs/db.md`.
- Перед работой с ценами, телефонами, VIN, валютами, справочниками — прочитай `docs/domain.md`.
- Перед спорным архитектурным решением — загляни в `docs/decisions.md`.

## Правила кода

- Проект и кэши живут на диске E (`E:\startup-project`, `E:\dev\.cache`), ничего не создавать на диске C.
- TypeScript strict, **без `any`**; неизвестные данные — `unknown` + zod.
- Каждая утилита — с тестами (`*.test.ts` рядом с файлом).
- **Цены — integer в целых единицах валюты** (доллары, сомы). Без float, центов, BigInt.
- **Телефоны — только E.164** через `normalizePhone`.
- Денормализованные поля `Listing` пишутся **только** через `packages/db/src/listings.ts`.
- Enum'ы: `schema.prisma` и `packages/core/src/enums.ts` меняются вместе.
- Миграции только через `prisma migrate`; применённые миграции не править.
- Не трогать сгенерированное: `packages/db/src/generated/**`, `dist/`, `pnpm-lock.yaml`.
- Секреты не коммитить и не выводить (строки подключения — в `.env.local`).
  Новая переменная — в `.env.example` и zod-схему.
- `Boolean?` из парсинга = «неизвестно», не подставлять `false`.
- Маленькие коммиты, Conventional Commits (`feat(core): …`, `fix(db): …`).

## Экономия контекста

- Ищи через grep/glob, читай только нужные файлы и куски, не перечитывай прочитанное.
- Тесты — точечно (`pnpm --filter <пакет> test <файл>`), весь набор — только перед коммитом.
- Длинный вывод команд обрезай (`tail`/`grep`), логи целиком не выводи.
- Задача больше 3 файлов — сначала короткий план.
- Отвечай кратко: что сделано, что проверено, что требует решения. Без пересказа кода.
- Агенты (`.claude/agents`): `test-runner` — после правок и перед коммитом; `reviewer` — diff перед коммитом; `parser-builder` — новый парсер источника; `data-qa` — после запуска парсера / при подозрении на мусор в БД; `ui-builder` — компоненты и витрина `apps/web`.
- Не добавляй в CLAUDE.md ничего без просьбы; новые решения — в `docs/decisions.md`.
